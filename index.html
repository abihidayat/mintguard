MintGuard

Check before you mint. MintGuard inspects a BNB Chain mint contract for Agent ID (.ai) holders before anyone spends a cent: is the source verified, is the free lane really still open, and does a zero-value mint actually simulate from an Agent ID wallet? Read-only — MintGuard never asks for approvals and never touches assets.

Anchor your check on-chain

Agent ID holders can anchor a report hash in the MintGuardLog contract — a public, tamper-proof trail of what was checked and when. The contract holds no assets, has no owner and no admin functions; the only gate is holding an Agent ID, read live from the official registry.

MintGuardLog (BNB Chain): 0x5897192ccde2f02636fd1eefd4d1951e84c93ec9

With a Binance Agentic Wallet agent (skill):

baw contract-call preview --chain bsc --from <your-address> --to 0x5897192ccde2f02636fd1eefd4d1951e84c93ec9 --abi-function "anchorCheck(address,bytes32)" --args '<target>,<reportHash>'
baw contract-call execute --request-id <requestId-from-preview>

Daily check-in for Agent ID holders: call checkIn() on the same contract, once per day.

How the check works

Contract is realLive bytecode must exist at the address on BNB Chain.
Source verifiedSourcify match for chain 56 — exact match means the published source is the deployed code.
Supply & free lanetotalSupply / maxSupply / freeMinted read live, so "sold out" is a fact, not a rumour.
Zero-value simulationThe contract's own mint entry points (from its verified ABI) are simulated with value 0 from an Agent ID wallet. A clean simulation means the free mint is genuinely open for that wallet; the revert reason is shown when it is not.
